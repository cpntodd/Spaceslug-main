# Vulkan runtime test acceptance

## Driver matrix

The API tests below are correctness gates and must be run with both the default
RADV driver (including RX580/gfx803) and lavapipe. The focused commands select
both tests explicitly; do not infer coverage from an aggregate CTest total.

| Test | Default RADV | lavapipe |
| --- | --- | --- |
| `tiny_profile_api` | `ctest --test-dir build/debug -R '^(tiny_profile_api|dataset_batch_buffer)$' --output-on-failure` | `VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json ctest --test-dir build/debug -R '^(tiny_profile_api|dataset_batch_buffer)$' --output-on-failure` |
| `dataset_batch_buffer` | `ctest --test-dir build/debug -R '^(tiny_profile_api|dataset_batch_buffer)$' --output-on-failure` | `VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json ctest --test-dir build/debug -R '^(tiny_profile_api|dataset_batch_buffer)$' --output-on-failure` |

Each command must report **2/2 tests passed**. The RADV command leaves
`VK_ICD_FILENAMES` unset so Vulkan selects the system default driver; the second
command pins lavapipe to the repository's CI ICD path.

## CI and full local runs

After configuring and building, CI-equivalent correctness runs are:

```sh
ctest --test-dir build/debug --output-on-failure
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json \
  ctest --test-dir build/debug --output-on-failure
```

The full run count is generated by the build and may grow as tests are added.
Documentation must not hard-code an old aggregate such as `39/39`; use the
focused matrix above when reviewing these two acceptance tests.

Performance tests are not part of this driver matrix: they are meaningful on
RADV only and skip their sweeps on lavapipe.
